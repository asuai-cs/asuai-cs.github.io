Autonomous Drone Navigation with Real-Time Obstacle Avoidance

A complete autonomous navigation system running on a Raspberry Pi 4, fusing data from a CNN-based vision pipeline, VL53L0X LiDAR, and MPU6050 IMU to navigate dynamic environments using Q-learning and PID control.

Python TensorFlow / CNN Q-Learning OpenCV Raspberry Pi 4 VL53L0X LiDAR MPU6050 IMU ArUco Markers PID Control

Overview

Autonomous navigation in dynamic environments requires more than a single sensor — no one modality provides sufficient information on its own. A camera captures rich visual context but gives no direct distance measurement. LiDAR measures distance precisely but has no semantic understanding of what it is detecting. An IMU tracks orientation and acceleration but drifts over time without external correction. This project combines all three into a unified sensor fusion loop running on a Raspberry Pi 4, enabling a drone to perceive its environment, plan actions in real time, and improve its decision-making through online reinforcement learning.

The system uses a pre-trained convolutional neural network to detect obstacles in the live camera feed and draw bounding boxes around them. Simultaneously, a VL53L0X LiDAR sensor provides precise distance readings and an MPU6050 IMU supplies orientation and acceleration data. These inputs form the state representation fed into a Q-learning agent that selects one of three actions — move forward, turn left, or turn right — at every frame. The Q-table is updated continuously during flight, so the drone's navigation policy improves the longer it operates. ArUco marker-based waypoints and a PID controller handle altitude and yaw stabilisation during guided navigation.

System Architecture

01

Sensor Fusion

At each 30 FPS cycle, three sensor streams are read in parallel: the camera frame via OpenCV, LiDAR distance via I2C from the VL53L0X (0–2 m range), and acceleration + gyro vectors from the MPU6050. These are combined into a unified state dictionary that captures both spatial proximity and flight dynamics.

→
02

Vision Pipeline

Each frame is resized to 224×224, normalised, and passed through a pre-trained lightweight CNN. If the obstacle confidence exceeds 0.5, OpenCV contour detection isolates the obstacle region and draws a bounding box on the live feed. The binary obstacle flag is added to the state.

→
03

Q-Learning Decision

The current state is looked up in the Q-table. With probability ε = 0.1 a random action is taken for exploration; otherwise the action with the highest Q-value is chosen. The reward function penalises obstacle detection (−100) and rewards clear-path proximity (inversely proportional to LiDAR distance).

→
04

Control & Update

The chosen action (forward, left, right) is dispatched to the motor controllers. A PID controller handles yaw and altitude corrections using ArUco marker position errors as the reference signal. After execution, the new state is observed and the Q-table is updated using the Bellman equation.

Key Features

📷

CNN Obstacle Detection

A TensorFlow CNN model pre-trained on drone camera imagery classifies each frame as obstacle or clear. When an obstacle is detected, OpenCV contour analysis localises it with a bounding box, giving both a binary detection signal and spatial position.

📈

Q-Learning Navigation

A tabular Q-learning agent with ε-greedy exploration maintains a growing Q-table keyed on the full sensor state. Learning rate α = 0.1 and discount factor γ = 0.9 balance immediate and future rewards, improving the policy with every flight cycle.

🔌

Multi-Sensor Fusion

LiDAR distance, IMU acceleration (x, y, z), and IMU gyro (x, y, z) are combined with the CNN obstacle flag into a single state vector. This gives the Q-agent richer situational awareness than any single sensor could provide alone.

🎯

ArUco Waypoint Navigation

Predefined waypoints are encoded as ArUco markers placed in the environment. The drone detects marker IDs and centres using OpenCV's ArUco library, computing position error relative to the target 3D coordinates stored in config.yaml.

⚙

PID Stabilisation

Separate PID controllers govern yaw and altitude, using marker centre offset and height error as inputs respectively. Gains (Kp = 0.8, Ki = 0.1, Kd = 0.3) were tuned empirically during indoor test flights to achieve stable hovering and smooth transitions.

🔧

Sensor Calibration Pipeline

A dedicated calibration script (Calibrate_Sensors.py) measures HC-SR04 ultrasonic readings at known distances (0.3 m, 0.5 m, 1.0 m) and captures ArUco marker pixel size at a known range, saving offset and scale factors to calibration.json for use at runtime.

Core Logic

The Q-learning decision and update loop — the brain of the navigation system — at every frame of the control cycle.

drone_navigation.py — Q-Learning Control Loop 
# Reward: penalise obstacle, reward proximity to clear path
reward = -100 if obstacle else (1.0 / (state['distance'] + 0.1))

# Choose action: epsilon-greedy exploration
action = choose_action(state)   # 0=forward, 1=left, 2=right

# Execute action on motor controllers
if   action == 0: move_forward()
elif action == 1: turn_left()
elif action == 2: turn_right()

# Observe new state and update Q-table (Bellman equation)
next_state = get_state()
update_q_table(state, action, reward, next_state)


def update_q_table(state, action, reward, next_state):
    current_q  = Q_TABLE[str(state)][action]
    max_next_q = max(Q_TABLE[str(next_state)])
    Q_TABLE[str(state)][action] += ALPHA * (
        reward + GAMMA * max_next_q - current_q
    )

PID controller used for yaw and altitude stabilisation during waypoint navigation:

Test_Navigation.py — PID Controller 
class PID:
    def __init__(self, Kp, Ki, Kd):
        self.Kp, self.Ki, self.Kd = Kp, Ki, Kd
        self.prev_error = 0
        self.integral   = 0

    def update(self, error, dt):
        self.integral  += error * dt
        derivative      = (error - self.prev_error) / dt
        output          = (self.Kp * error
                         + self.Ki * self.integral
                         + self.Kd * derivative)
        self.prev_error = error
        return output

# Yaw: centre marker on camera frame (error = pixel offset / 320)
yaw_error = (marker_center_x - 320) / 320.0
yaw_speed = yaw_pid.update(yaw_error, dt)

# Altitude: drive to target height from config.yaml
alt_error = target_z - current_height
alt_speed = alt_pid.update(alt_error, dt)

The system was tested in a controlled 3×3 m indoor environment using three ArUco marker waypoints. Sensor calibration was performed before each session using the dedicated calibration script, ensuring accurate distance and marker size readings.
