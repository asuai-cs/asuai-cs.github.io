Research

Hardware Trojan Detector

A formal verification framework for detecting malicious circuit modifications in RTL chip designs using SMT-based property checking.

Python Z3 SMT Solver Verilog Formal Verification Hardware Security Flask

Overview

Hardware Trojans are malicious circuit components deliberately inserted into a chip design, often during fabrication or third-party IP integration. Once activated by a rare trigger condition, they can leak sensitive information, degrade performance, or cause catastrophic failures — all without leaving any trace visible to traditional testing methods.

This project implements a formal verification framework that analyses Register-Transfer Level (RTL) Verilog designs using the Z3 SMT solver to mathematically prove or disprove security properties. Rather than relying on simulation, which cannot exhaustively explore all input combinations, formal verification provides an ironclad guarantee: if a property holds, it holds for every possible input and circuit state. The framework was applied to an AES encryption core deliberately seeded with a Trojan — a rare-trigger key leakage payload — and successfully detected it.

How It Works

01

Parse

The VerilogParser reads the RTL design file, extracts module ports, registers, wires, and always blocks. It simultaneously scans for known Trojan signature patterns — rare trigger conditions, key-conditional logic, and hidden state machines — flagging suspicious constructs before formal checking begins.

→
02

Verify

Security properties are loaded from a specification file and evaluated against the parsed design using Z3. The verifier handles ForAll, Exists, and Implies quantified expressions. Dedicated Trojan-specific checks are then run — including rare signal activation analysis and key leakage detection — to catch payloads that general property checks may miss.

→
03

Report

Results are serialised to a structured JSON report, then converted to a clean HTML security report including a Plotly bar chart visualising properties checked, violations found, and Trojan findings. A lightweight Flask API endpoint allows the verifier to be called programmatically, making it easy to integrate into a CI/CD pipeline for automated hardware security checks.

Key Features

🔍

Pattern Pre-Scanning

Before formal verification, the parser pre-scans for known Trojan signatures using regex pattern matching — catching rare-condition triggers, key leakage assignments, and hidden state logic early.

✅

SMT-Based Property Checking

Security properties written as logical expressions are encoded into Z3 constraints. The solver proves each property exhaustively across all possible circuit states — not just sampled inputs.

🔒

Key Leakage Detection

A dedicated check tests whether any trigger condition causes key material to appear in ciphertext output — the exact class of Trojan found in the AES benchmark, where ciphertext[7:0] <= key[7:0] was activated by a rare dual-signal trigger.

📊

Automated HTML Reporting

Each verification run produces a structured HTML report with a Plotly visualisation of results — properties checked, violations found, and Trojan findings — making results accessible without reading raw JSON.

🔗

REST API Integration

A Flask API exposes the verifier as a /verify/<design> endpoint, enabling integration into automated design flows and CI/CD pipelines for continuous hardware security monitoring.

⚡

Side-Channel Property Checks

Beyond Trojan detection, the framework checks for constant-time execution and secret-dependent branching — two key properties required to prevent timing and power side-channel attacks.

Core Detection Logic

The snippet below shows the dedicated Trojan detection method — the check that caught the key leakage payload in the AES benchmark design.

formal_verifier.py — Key Leakage Check 
# Check 2: Key leakage via rare trigger condition
if 'ciphertext' in z3_vars and 'key' in z3_vars:
    key_leak = z3_vars['ciphertext'][7:0] == z3_vars['key'][7:0]
    self.solver.add(key_leak)

    if self.solver.check() == sat:
        model = self.solver.model()
        self.results['trojan_findings'].append({
            'type': 'key_leakage',
            'severity': 'critical',
            'description': 'Key material leaked to ciphertext',
            'bits': 'ciphertext[7:0]',
        })
        self.results['violations_found'] += 1
        print("🚨 CRITICAL: Key leakage detected")
    self.solver.reset()

The Verilog Trojan it catches — embedded inside the AES core — looks like this:

aes_core.v — Trojan Payload 
// Trojan trigger: activates only when both rare signals are high
wire trojan_trigger = rare_signal1 & rare_signal2;

// Trojan payload: leaks the first byte of the key into ciphertext
if (trojan_trigger) begin
    ciphertext[7:0] <= key[7:0];   // leak key byte
    ciphertext[127:8] <= 120'b0;       // clear other bits
end
