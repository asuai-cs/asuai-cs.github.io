IoT-Based Smart Energy Monitoring System

A full-stack IoT system that monitors household energy consumption in real time using an ESP32 and INA219 sensor, streams data over MQTT, predicts future usage with a machine learning model, and visualises everything on a live React dashboard.

ESP32 INA219 Sensor MQTT / Mosquitto Python / Flask SQLite scikit-learn React Chart.js Arduino / C++

Overview

Energy awareness in households is increasingly important, but most commercial meters provide only aggregate monthly readings with no actionable real-time insight. This project builds a complete end-to-end monitoring system from the sensor all the way to a live web dashboard — covering embedded firmware, cloud data ingestion, machine learning predictions, a REST API, and a React front-end — as a single integrated platform.

An INA219 current and voltage sensor is wired in series with a household appliance and connected to an ESP32 microcontroller. Every five seconds, the ESP32 reads voltage, current, and computed power, then publishes the values as a JSON payload over MQTT to a Mosquitto broker. A Python cloud server subscribes to this stream, stores each reading in an SQLite database, and runs a linear regression model trained on the REDD energy dataset to predict the next power reading. A Flask REST API exposes the historical data, and a React dashboard consumes both the MQTT stream and the API to show live metrics and a Chart.js time-series plot of measured versus predicted power.

System Architecture

01

Edge: ESP32 Firmware

The INA219 is initialised over I2C (SDA: GPIO 21, SCL: GPIO 22) for a 32 V / 2 A measurement range. Every 5 seconds the firmware reads bus voltage and current, computes power, validates against NaN, serialises to JSON, and publishes to the energy/data MQTT topic. An automatic reconnection loop handles broker outages.

→
02

Broker: Mosquitto MQTT

A Mosquitto broker (deployable on AWS EC2, Raspberry Pi, or local machine) receives published payloads and fans them out to all subscribers. The Python server and React dashboard both subscribe to energy/data, allowing real-time delivery to both the storage layer and the visualisation layer simultaneously.

→
03

Cloud: Python Server + ML

On each received message, the server stores the reading in SQLite with a timestamp, then triggers the prediction pipeline. A linear regression model — trained on REDD refrigerator data with weights derived from the last three time steps — predicts the next power value and writes it back to the database alongside the measured reading.

→
04

Frontend: React Dashboard

The dashboard connects to the MQTT broker over WebSocket for live metric cards (voltage, current, power, predicted power) and polls the Flask /history endpoint for the last 100 records. Chart.js renders a dual-line time-series comparing measured and predicted power consumption.

Key Features

⚡

Real-Time Sensor Telemetry

The INA219 measures voltage (V), current (mA), and computed power (W) at 5-second intervals. Readings are validated before publishing — NaN values trigger an error flag and skip the MQTT publish cycle to prevent corrupt data reaching the cloud.

📡

MQTT Data Streaming

JSON payloads are published to energy/data over MQTT with an automatic broker reconnection loop. This decouples the ESP32 from the cloud layer — the firmware continues collecting data locally even during brief network outages, publishing when reconnected.

📈

ML-Based Consumption Prediction

A linear regression model trained on the REDD public energy dataset uses the last three time-step power values as features to predict the next reading. Model weights are pre-trained offline and embedded in the server, enabling instant predictions without retraining on every message.

📋

SQLite Data Persistence

Every incoming reading — voltage, current, power, and predicted power — is timestamped and stored in an SQLite database. The schema is initialised automatically on first run. The last 100 records are exposed via the Flask API for dashboard consumption.

🌐

Flask REST API with CORS

A lightweight Flask server exposes a GET /history endpoint returning the most recent 100 records as JSON. Flask-CORS handles cross-origin access, allowing the React dashboard to be hosted on a different domain or port without browser security errors.

📊

Live React Dashboard

Four metric cards display live voltage, current, power, and predicted power updated on each MQTT message. A Chart.js line chart plots the full historical record with separate series for measured and predicted power, giving immediate visual insight into usage patterns and forecast accuracy.

Core Implementation

The ESP32 firmware loop — reading the INA219, building the JSON payload, and publishing over MQTT every 5 seconds:

Energy_Monitor.ino — ESP32 Firmware Loop 
void loop() {
    if (!client.connected()) reconnect();
    client.loop();

    // Read INA219 sensor
    float voltage = ina219.getBusVoltage_V();
    float current = ina219.getCurrent_mA();
    float power   = voltage * (current / 1000.0);

    if (isnan(voltage) || isnan(current)) {
        Serial.println("Sensor read error");
        delay(5000);
        return;
    }

    // Publish JSON to MQTT topic "energy/data"
    String payload = "{\"voltage\":"  + String(voltage, 2) +
                     ",\"current\":" + String(current, 2) +
                     ",\"power\":"   + String(power,   2) + "}";
    client.publish(mqtt_topic, payload.c_str());
    delay(5000);
}

The server-side prediction pipeline — triggered on every incoming MQTT message:

Energy_Server.py — ML Prediction on Incoming Data 
def predict_power():
    df = pd.read_sql_query(
        "SELECT timestamp, power FROM energy_data ORDER BY timestamp DESC LIMIT 100",
        sqlite3.connect(DB_NAME)
    )
    if len(df) < 10: return   # need sufficient history

    # Predict using pre-trained REDD model weights
    X_last = df['time_index'].values[-3:]
    predicted = (
        MODEL_WEIGHTS[0] * X_last[0] +
        MODEL_WEIGHTS[1] * X_last[1] +
        MODEL_WEIGHTS[2] * X_last[2] +
        MODEL_INTERCEPT
    )

    # Write prediction back alongside the measured reading
    c.execute("UPDATE energy_data SET predicted_power=? WHERE timestamp=?",
              (predicted, df['timestamp'].iloc[-1]))

The system was verified end-to-end using a 60 W lamp as the test load, confirming accurate INA219 readings via the Serial Monitor and validating MQTT message delivery with MQTT Explorer. The Flask API was tested with curl to confirm correct JSON formatting and CORS headers. The React dashboard was validated locally with npm start, with chart rendering confirmed against the stored SQLite records. The linear regression model was trained offline on the REDD public energy dataset and its weights embedded directly in the server for zero-latency predictions.
