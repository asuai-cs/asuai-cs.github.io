Research

PCHB Trojan Detector

A formal verification engine for detecting Hardware Trojans in asynchronous Pre-Charge Half Buffer (PCHB) circuits, targeting handshake violations, data leakage, and timing anomalies using Z3 SMT-based property checking.

Python Z3 SMT Solver Verilog Formal Verification PCHB / QDI Circuits Flask NULL Convention Logic

Background

Pre-Charge Half Buffer (PCHB) circuits are a class of Quasi-Delay Insensitive (QDI) asynchronous logic that operates without a global clock. Instead of relying on timing assumptions, PCHB circuits use a four-phase handshake protocol — request, acknowledge, data valid, return to NULL — to coordinate computation. This makes them inherently resilient to timing variations and electromagnetic interference, which is why they are used in safety-critical domains such as space systems, automotive electronics, and cryptographic hardware.

However, their asynchronous nature creates a unique attack surface. A Hardware Trojan inserted into a PCHB circuit can exploit illegal input combinations that arise during the NULL-to-DATA transition, activating a malicious payload under conditions so rare that standard simulation testing will never encounter them. This project builds a formal verification engine specifically designed to detect exactly that class of threat.

How It Works

01

Load Design

The verifier parses the Verilog RTL design and extracts all PCHB-specific signals — req, ack, data, en, and their next-state counterparts. Each signal is encoded as a Z3 Boolean variable, creating a formal model of the circuit's state space for exhaustive analysis.

→
02

Verify Properties

Three classes of properties are checked in sequence. Handshake compliance enforces the four-phase protocol — request must precede acknowledge, acknowledge must clear before the next request. Data stability ensures no data bit changes while the enable signal is active. Trojan pattern matching converts JSON-defined Trojan signatures into Z3 constraints and checks for satisfiability.

→
03

Report

Results are saved to a structured JSON report, then rendered into an HTML report via generate_report.py. Each detected Trojan is listed with its name, type, severity, and the Z3 counterexample model — the exact signal values that activate the malicious behaviour. A Flask API at /verify exposes the engine for programmatic use.

Trojan Classes Detected

The framework detected two Hardware Trojans in the PCHB adder benchmark. Both exploit conditions that are impossible under normal operation but become reachable under adversarial input combinations.

⚠

Early-Ack Trojan

Type: Handshake Violation — Severity: Critical

Triggers when req is asserted but en is low, causing ack to fire prematurely. This breaks the four-phase handshake contract, corrupting downstream computations silently. Logic pattern: req && !en && ack.

🔒

Data-Leak Trojan

Type: Information Leakage — Severity: High

Activates when enable is low but two specific data bits (data_0 and data_1) are simultaneously high — an illegal state in valid PCHB encoding. Under this condition, sensitive data propagates outside the circuit's intended boundary. Logic pattern: !en && data_0 && data_1.

Key Features

🔄

Four-Phase Handshake Verification

Formally encodes and checks all three rules of the PCHB handshake protocol using Z3 Implies constraints, guaranteeing correctness across every possible signal combination.

✅

Data Stability Checking

Verifies that all 32 data bits remain stable during the evaluation phase by encoding bit-level stability constraints — catching any Trojan that introduces spurious transitions.

📋

JSON-Driven Trojan Patterns

Trojan signatures are defined in pchb_properties.json as named, typed, and severity-rated logic expressions. New patterns can be added without touching the verifier code — making the framework easily extensible.

🔌

Scoped Z3 Checking

Each Trojan pattern is checked in an isolated solver scope using push() and pop(), preventing constraint accumulation from interfering across checks — a critical correctness detail in formal verification.

📊

Counterexample Models

When a Trojan is detected, Z3 returns the exact signal assignment that activates it. These counterexample models are captured and included in the HTML report, giving engineers a concrete starting point for analysis.

🔗

REST API

A Flask endpoint at POST /verify runs the full verification pipeline and returns a JSON response with terminal output and the path to the generated HTML report — ready for CI/CD integration.

Core Detection Logic

The snippet below shows how a Trojan pattern defined in JSON is converted into a Z3 constraint, checked for satisfiability, and recorded with its counterexample model.

pchb_verifier.py — Trojan Pattern Detection 
def _detect_trojans(self, patterns: list):
    for pattern in patterns:
        constraint = self._pattern_to_z3(pattern["logic"])
        if constraint is not None:
            self.solver.push()          # isolate this check
            self.solver.add(constraint)

            if self.solver.check() == sat:
                model = self.solver.model()
                self.results["trojan_detections"].append({
                    "name":     pattern["name"],
                    "type":     pattern["type"],
                    "severity": pattern["severity"],
                    "model":    str(model)   # counterexample
                })
            self.solver.pop()           # restore solver state
