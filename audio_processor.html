FPGA-Based Real-Time Audio Signal Processor

A hardware audio processing system implemented in VHDL on a Xilinx Zynq-7000 FPGA, capturing audio via I2S, transforming it in the frequency domain using a 256-point FFT, applying real-time equalization, and transmitting processed audio back through a WM8731 codec.

VHDL Xilinx Zynq-7000 I2S Protocol WM8731 Codec 256-Point FFT Vivado Design Suite C / Embedded Python

Overview

Real-time audio processing at the hardware level demands a fundamentally different approach from software implementations. Every operation must complete within a deterministic time window — in this case, within the 48 kHz sampling period of the WM8731 audio codec. This project builds the entire audio processing chain in VHDL, running directly on the programmable logic of a Xilinx Zynq-7000 FPGA (ZedBoard), with no operating system or software stack in the signal path.

The system captures audio through a microphone connected to the WM8731 codec via the I2S protocol, feeds the samples into a Vivado-generated 256-point FFT IP core for spectral analysis, applies a three-band equalizer (low, mid, high) to the frequency-domain data, and transmits the processed audio back to the codec's DAC for speaker output. The codec itself is configured over I2C from the Zynq's processing system, setting 48 kHz sampling, 16-bit resolution, and slave I2S mode.

Signal Flow

01

I2S Receive

A state machine samples the ADCDAT line on each falling edge of BCLK, assembling a 16-bit audio sample from the left channel. Clocks are derived from the 100 MHz system clock: MCLK at ~12.288 MHz, BCLK at ~3.072 MHz, and LRCLK at 48 kHz.

→
02

FFT Processing

Captured samples stream into the Vivado FFT IP core via an AXI-Stream interface. The core performs a 256-point fixed-point FFT at 16-bit precision in pipelined streaming mode, delivering frequency-domain bins with approximately 1 ms processing latency.

→
03

Equalize

FFT output bins are divided into three bands — low (bins 0–63, 0–3 kHz), mid (bins 64–191, 3–9 kHz), and high (bins 192–255, 9–12 kHz). Each band is multiplied by a configurable Q15 fixed-point gain, then the results are summed to form the processed output sample.

→
04

I2S Transmit

The processed 16-bit sample is serialised bit-by-bit onto the DACDAT line in sync with BCLK and LRCLK, delivering the equalised audio to the WM8731 DAC for speaker output.

Hardware & Codec Configuration

The WM8731 audio codec is connected to the ZedBoard via I2S signal lines (MCLK, BCLK, ADCLRC, DACLRC, ADCDAT, DACDAT) and configured over I2C before audio processing begins. The Zynq processing system sends configuration commands via its on-chip I2C controller to the codec's 7-bit address 0x1A. Key register settings establish 48 kHz sampling, enable the microphone input, disable the high-pass filter for clean testing, and activate the codec in I2S 16-bit slave mode.

wm8731_config.c — Codec Initialisation over I2C 
// Configure WM8731 registers via Zynq PS I2C controller
write_wm8731(0x0F, 0x000);  // R15: Reset codec
write_wm8731(0x04, 0x010);  // R4:  Enable microphone input
write_wm8731(0x05, 0x000);  // R5:  Disable high-pass filter
write_wm8731(0x06, 0x000);  // R6:  Power on all blocks
write_wm8731(0x07, 0x00A);  // R7:  I2S, 16-bit, slave mode
write_wm8731(0x08, 0x000);  // R8:  48 kHz sampling, normal mode
write_wm8731(0x09, 0x001);  // R9:  Activate codec

Key Features

⏱

Hardware Clock Generation

All I2S clocks — MCLK (12.288 MHz), BCLK (3.072 MHz), and LRCLK (48 kHz) — are derived from the 100 MHz system clock via a VHDL counter-based divider, eliminating the need for external clock sources.

🎤

I2S State Machine

A three-state FSM (IDLE → LEFT → RIGHT) handles the I2S receive protocol, capturing 16 bits per left-channel sample and triggering the FFT pipeline as each frame completes.

📈

256-Point FFT via Vivado IP

The Xilinx FFT IP core (v9.1) is instantiated with pipelined streaming I/O, fixed-point 16-bit data format, and natural output ordering — delivering ~1 ms processing latency at 100 MHz.

🎵

Three-Band Equalizer

FFT bins are grouped into low, mid, and high frequency bands. Each band is scaled by a Q15 fixed-point gain stored in a 48-bit signal, enabling independent boost or attenuation of each frequency range.

🔌

AXI-Stream Interface

The I2S receiver feeds data into the FFT core via AXI-Stream handshake signals (tvalid, tready), ensuring correct flow control and preventing data loss under varying processing loads.

🔧

VHDL Testbench with Real Audio

A Python script (Generate_Audio_Test.py) extracts 16 samples from a real 48 kHz speech WAV file and formats them as a VHDL array. The testbench feeds these samples into the design and verifies equalized output in Vivado simulation.

Core VHDL — I2S Receiver

The snippet below shows the I2S receive state machine that captures audio samples from the WM8731 ADC and hands them to the FFT pipeline.

audio_processor.vhd — I2S Receiver FSM 
process(bclk_int, reset)
begin
    if reset = '1' then
        i2s_state    <= IDLE;
        bit_counter  <= 0;
        audio_in     <= (others => '0');
        fft_tvalid_in <= '0';
    elsif falling_edge(bclk_int) then
        case i2s_state is
            when IDLE =>
                if lrclk_int = '0' then
                    i2s_state   <= LEFT;
                    bit_counter <= 15;
                end if;
            when LEFT =>
                audio_in(bit_counter) <= adcdat;
                if bit_counter = 0 then
                    fft_data_in   <= audio_in;  -- send sample to FFT
                    fft_tvalid_in <= '1';
                    i2s_state     <= RIGHT;
                    bit_counter   <= 15;
                else
                    bit_counter <= bit_counter - 1;
                end if;
            when RIGHT =>
                if bit_counter = 0 then
                    i2s_state     <= IDLE;
                    fft_tvalid_in <= '0';
                else
                    bit_counter <= bit_counter - 1;
                end if;
        end case;
    end if;
end process;

The system was simulated in Vivado using real speech samples extracted from a 48 kHz WAV file. I2S timing, FFT accuracy, and equalizer gain application were all verified in the waveform viewer. The design was synthesized and implemented for the Zynq-7000 (XC7Z020), with resource utilisation optimised across LUTs and DSP slices. An Integrated Logic Analyzer (ILA) was used for on-hardware debugging of signal paths post-deployment.
